# Brainstorm — minimax-ui-redesign

背景：用户以 MiniMax Code 截图（图一 / 图二 / 图三）为目标，重构 shy 的渲染层 UI。现有 shy 已具备对话/记忆/技能/日历/设置五视图，并有「minimax 风格右侧 Inspector 面板」雏形；本次把整站视觉与信息层级对齐截图。

决议链（已与用户收敛）：

- Q1 改造目标？→ **shy**（本工作区 Electron Agent 客户端），非 DSH web。
- Q2 导航映射？→ **混合**：保留 shy 真实功能，按图一外形重排；图一的 网站/连接手机/远程控制 无对应 → **省略**。
- Q3 项目分组？→ **不做项目分组**，底部区块仅展示会话列表（按图一风格）。
- Q4 始终授权开关？→ **真做**：主进程加「默认自动批准工具」配置，联动现有 `confirmTool` 闸门，开关本地持久化。
- Q5 模型选择器？→ **展示型**：只显示当前模型名（来自 `ModelSettings.model`），不做多模型切换。
- Q6 分支 / 本地模式 / 打开终端？→ **不做**（无 git 操作、无「打开终端」、忽略 MiniMax 的本地/远端模式）。
- Q7 范围？→ **图一 + 图二 + 图三 一次做完**（左侧栏 / 主区空态 / 对话区 + 环境面板）。
- Q8 流程？→ 开会话式讨论收敛 → `openspec changenew` 建档，验收后再进 apply。
- Q9 目标模式切换？→ **去掉独立的 目标/交互式 ModeToggle**；改为在输入框敲 `/` 弹出**命令菜单**：含「模式选择（交互式 / 目标）」与「相关技能选择（来自 `listSkills`，可搜索）」。选模式 → 设置当前会话模式；选技能 → 在草稿插入技能引用，令 `skills/match.ts` 命中并路由该技能。

验收锚点（供 `/opsx:verify` 手工点验）：
1. 左侧栏呈图一布局（新建任务 / 搜索 / 导航 / 会话列表 / 底部账户卡），真实功能可导航。
2. 空态呈图二布局（居中 logo+标语 / 大输入框 / 「始终授权」toggle / 展示型模型选择 / 功能 pills），输入可发送。
3. 顶栏不再有独立的 交互式/目标 切换；在输入框敲 `/` 弹出命令菜单，含模式与技能选择；目标模式不再有「验证命令」输入框，直接进入目标推进。
4. 对话区呈图三布局（消息线程 / 工具卡片 / 「已编辑 N 个文件」卡片 / 右侧环境面板），流式与工具渲染正常。
5. 「始终授权」开启后重开 app 生效；开启时工具不再逐条弹确认。
6. `npm run typecheck` 通过；各视图无渲染错误。
